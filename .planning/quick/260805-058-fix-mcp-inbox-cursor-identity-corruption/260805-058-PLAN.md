<objective>
Close the MCP inbox cursor identity-corruption bug class reported against `famp 1.1.0-rc.1`
after an overnight multi-agent run. Three defects, one root cause chain:

1. `mcp/session.rs` holds `active_identity` in a process-global `OnceLock<Mutex<SessionState>>`.
   Claude Code subagents issue MCP calls through the PARENT window's MCP server process, so a
   subagent calling `famp_register` silently rebinds the whole window.
2. `mcp/tools/inbox.rs::call` reads `session::active_identity()` TWICE — once to build
   `ListArgs.act_as` (the read), once to pick the `.cursor` filename (the write-through). A
   `famp_register` landing between them writes the OLD identity's `next_offset` into the NEW
   identity's cursor file. Live proof on disk: `~/.famp/mailboxes/.lane-x-merge.cursor` == 14334,
   exactly the byte size of `LANE-L.jsonl`, while `lane-x-merge.jsonl` is only 9865 bytes.
3. The write-through is deliberately monotonic (`current.max(next_offset)`) with no EOF clamp, so
   a cursor that lands past EOF NEVER recovers. The identity is then permanently blind —
   `famp_inbox` returns `{"entries": []}` forever, indistinguishable from "no new mail". Four live
   victims on this machine; one caused a 52-minute loss of a critical-path work brief.

Purpose: an agent must never be silently blinded, and a subagent must never be able to hijack its
parent window's identity without a loud, actionable error.

Output: the TOCTOU closed, an EOF clamp that self-heals the existing corrupt cursors on next read,
an explicit `rebind: true` opt-in for identity takeover, and a module doc that stops lying about
what the code does.

**Not tracer-shaped, deliberately.** This is a single-layer CLI/MCP bugfix across two
independent defect surfaces (cursor arithmetic; identity binding). Each task is independently
end-to-end verifiable on its own; a thin vertical slice through both would prove nothing the two
tasks do not already prove separately.
</objective>
