<objective>
Lock in TEST-02: the live two-process signed cross-host E2E runs on every
`just ci`, not behind a manual or ignored path — and pin the D-05 CI-safety
properties that make it safe to run in CI unattended.

Per D-03/D-04 and the research CRUX (verified live this session): Phase 9's
`crates/famp-gateway/tests/e2e_cross_host_delivery.rs` ALREADY runs green under
`cargo nextest run --workspace` (969/969, the E2E in 9.3s) — exactly what
`just ci` → `just test` invokes. The prior "nextest hang" was a cold-build
compile timeout, not a stall. So there is **no new test-group and no new E2E to
build** (D-03: do not author a second E2E). The remaining work is two
lightweight, durable **regression guards** over the existing test:

1. A presence/enablement guard (TEST-02, D-04): fail CI if a future change
   deletes the E2E test fn or slaps the ignore attribute on it.
2. A hermetic-property guard (D-05): assert the E2E is already CI-safe —
   `ChildGuard`-reaps every spawned broker/gateway child, binds ephemeral ports,
   isolates `FAMP_HOME`/`--socket` per process in a tempdir, uses the fixture
   certs, and never touches a developer's `~/.famp/` — so a future edit cannot
   silently regress those properties.

Both are verifications of the EXISTING test's already-true properties (confirmed
by inspection: `ChildGuard` via `common/child_guard.rs`, `127.0.0.1:0` ephemeral
bind, `tempfile::TempDir`-backed `FAMP_HOME` + per-side `--socket`, fixture certs
at `crates/famp/tests/fixtures/cross_machine/{alice,bob}.{crt,key}`). Do NOT
rewrite the E2E — only pin its properties.

Purpose: Prevent silent erosion of the CI-gated, leak-free E2E without
rebuilding infra (D-04: do NOT satisfy TEST-02 via `#[ignore]` or a manual
recipe — these guards enforce the opposite; D-05: keep it hermetic/CI-safe).

Output: `crates/famp-gateway/tests/e2e_ci_gate_guard.rs` (both guards).
</objective>
