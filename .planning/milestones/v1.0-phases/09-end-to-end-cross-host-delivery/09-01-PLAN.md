<objective>
Build the three gateway relay primitives every downstream Phase 9 plan hangs off, and scaffold the two new modules (egress/ingress) plus their crate dependencies so Wave 2 can proceed in parallel with zero shared-file contention.

Today `ProxiedPrincipal` only holds its UDS connection open for liveness (the field is dead-code-suppressed `_client`); `GatewayRegistry::get` is immutable-only; and `verify_inbound<B>` is generic over exactly one body class. Phase 9's drain/deliver flow needs a mutable send/drain method (per 09-RESEARCH §1), a mutable registry accessor, and a class-dispatching verify (per 09-RESEARCH §4). This plan adds all three, keeping each an exact mirror of its same-file analog (per 09-PATTERNS).

Purpose: Deliver the shared plumbing so egress (09-02) and ingress (09-03) build only their own new files.
Output: send_recv, get_mut, verify_inbound_any, two registered module stubs, and the Cargo dependency surface for the HTTP relay.
</objective>

| remote gateway → local bus | Cross-host bytes become a local `BusMessage::Send`; only `verify_inbound_any` stands between untrusted bytes and a trusted delivery. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Spoofing | verify_inbound_any | critical | mitigate | Preserve the exact two-gate order (unpinned hard-reject BEFORE decode); per-class unit tests assert both reject reasons on an empty and wrong-key keyring. |
| T-09-02 | Tampering | ProxiedPrincipal::send_recv | high | mitigate | send_recv performs no envelope rewriting; it is a thin pass-through so no relay code can silently mutate task_id/class/body. |
| T-09-SC | Tampering | cargo dependency adds | low | accept | Zero new external packages — every crate added is a workspace member or an already-pinned transitive dep of famp-transport-http (09-RESEARCH Package Legitimacy Audit: N/A). |
