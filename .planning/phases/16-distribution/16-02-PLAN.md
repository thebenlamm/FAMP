<objective>
Make the release pipeline self-policing: a drift gate so the generated `release.yml` and the committed
installers cannot silently diverge from `[workspace.metadata.dist]`, a structural gate encoding DIST-05's
"only the tag-triggered workflow produces artifacts", and shellcheck coverage of the installers.

Purpose: `release.yml` and the installers are generated files that only ever run at tag time. Without a
gate, a hand edit or a stale regeneration is invisible until a release is already wrong — and this
project's standing rule is that an unwired verification decays silently.

Output: one additive workflow, one script, three `just` recipes.
</objective>

    Assertion 1 — sole producer. Scan every file under `.github/workflows/` other than `release.yml` for

    `softprops/action-gh-release`, `actions/upload-release-asset`, and `ncipollo/release-action`. Any match

    `count == 0`-on-unfiltered-file check.

    contains a `tags:` key nested under `push:`. Note deliberately, in a comment in the script, that

    later. What DIST-05 forbids is a *second producer* of artifacts, which Assertion 1 covers.

    scratch copy of one existing workflow, confirm the script exits non-zero and names that file, then
