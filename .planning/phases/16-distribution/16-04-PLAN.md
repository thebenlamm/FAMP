<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Documentation -> a new user's shell | Whatever command a doc prints is what a trusting reader pastes and runs; a wrong command is a real failure delivered to a real machine. |
| Doc claim -> user's security expectation | A doc that overclaims what checksum verification proves induces misplaced trust in an unsigned artifact. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-11 | Spoofing | A documented install command resolving to a public registry name this project does not own | high | mitigate | Every bare-name install form is removed from the four docs and the compiled test asserts its absence; D-01 forbids claiming the name instead. |
| T-16-02 | Tampering, Spoofing | User over-trusting an unsigned artifact because the docs overstate what checksums prove | medium | mitigate | D-06's exact sentence is asserted verbatim, and a companion assertion forbids stronger authenticity/provenance claims. |
| T-16-03 | Tampering | `curl \| sh` transport | medium | mitigate | Docs use HTTPS release-asset URLs only, offer the fetch-then-read form, and give a `download/<tag>` pinning form. |
| T-16-12 | Repudiation | A docs-only regression landing with zero check-runs and being read as green | high | mitigate | `install-docs-gate.yml` covers the `paths-ignore`d commit shape; the acceptance criterion treats `total_count == 0` as blocking. |
</threat_model>
