<assumption_delta_decision>
The `assumption-delta` detector fired (`kind: pluralization`, terms `second` / `fallback`). The core
assumption losing its monopoly is **the install path**: until this phase there was exactly one way to
obtain FAMP (build from source), and exactly one binary the word "install" referred to (`famp`, via
`just install`). This phase introduces a second install path and widens the binary set to three.

- **Primary noun (generalized identity):** *the FAMP binary set* — `famp`, `famp-gateway`, `famp-relay` —
  obtained via *a release artifact*. Not "`famp`, built from source."
- **Decision: `promote`.** The prebuilt-binary path becomes primary; the from-source path is demoted to
  one variant of it (the contributor/fallback variant). This is not a planner preference — DIST-04
  requires it literally ("onboarding docs **lead with** the binary install path"), and 16-04 encodes the
  ordering mechanically. Adding the binary path *alongside* an equally-primary source path is the
  add-alongside failure this checkpoint exists to catch, and it is explicitly rejected here.
- **Convergence guard:** D-07's `install-path = "CARGO_HOME"` makes both variants write to the same
  `~/.cargo/bin`, so the promotion does not fork the identity of "the installed famp."
- **Invariant test encoding the generalized intent:** `crates/famp/tests/install_docs_accuracy.rs`
  (16-04) goes red the instant any doc reintroduces a from-source-first ordering, on any of the four
  onboarding surfaces.
</assumption_delta_decision>
