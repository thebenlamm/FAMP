<objective>
D-05 / ADDR-03 — the phase's one genuinely-unresolved sub-problem. Give the CLI a single host-level own-domain source (RESEARCH option (a)), read in one place, that both `famp send` (plan 03, stamps envelope `from`) and `famp peer export` (produces the peer-pinned label) consume. This structurally enforces the load-bearing invariant: **envelope `from` authority == the label the peer pinned the sender's gateway key under** (`verify.rs:58-66` does `keyring.get(peek_sender(from))`). Three independent OS processes can only agree without drift by reading one shared value.

Purpose: close the `from == pinned-label` coupling that today lives in two unrelated human-typed places with nothing enforcing agreement.
Output: an own-domain resolver module + a CliError for the missing/invalid case + peer-export label coupling, all unit-tested.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-11-03 | Spoofing | own-domain drift (from != pinned-label) | high | mitigate | Single-source own-domain: `famp send` `from` and `peer export` label read one value → cannot diverge into an `UnpinnedKey` self-DoS |
| T-11-04 | Tampering | invalid/injected own-domain authority | medium | mitigate | `validate_authority` on the resolved value before it stamps `from` or a pin label |
| T-11-05 | Information Disclosure | own-domain file readable | low | accept | own-domain is a public DNS-style authority string, not a secret; no key material stored |
