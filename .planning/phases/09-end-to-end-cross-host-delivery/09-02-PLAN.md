<objective>
Build the outbound half of the cross-host relay: a per-principal drain loop that pulls whatever a local agent addressed to a gateway-backed remote principal, adds the federation fields, signs with the gateway's persisted identity key, and ships the bytes to the peer gateway over HTTPS.

This implements D-03 egress. The drained mailbox entry is a plain unsigned local-bus JSON object (per 09-RESEARCH §5 — the local path carries no signature and no federation fields), so the gateway mutates that raw Value in place and signs it — the content-transparent path that lets GW-03's FSM advance byte-for-byte on the far side.

Purpose: Make "A's local agent sends to remote principal bob" become "signed HTTP POST to B's gateway."
Output: `egress.rs` with a signing helper and a `run_egress` drain loop.
</objective>

    Add `pub async fn run_egress(name: String, registry: Arc<Mutex<GatewayRegistry>>, transport: Arc<HttpTransport>, sk: FampSigningKey, vk: TrustedVerifyingKey)`. CRITICAL shared-connection contract (load-bearing for GW-02): the same backed `ProxiedPrincipal` (e.g. B's `alice` stand-in) is touched by BOTH this egress loop (drains replies addressed to `alice`) AND the 09-03 ingress handler (sends A's inbound requests into local `bob` via `get_mut("alice")`). Both go through the SINGLE `Arc<Mutex<GatewayRegistry>>`. Therefore `run_egress` must NOT hold a standalone long-lived `&mut ProxiedPrincipal` across a long Await. Instead, per loop iteration: (1) acquire `registry.lock().await`, (2) `get_mut(&name)`, (3) `send_recv(BusMessage::Await { timeout_ms: 1000, task: None })` with a SHORT timeout, (4) collect the `AwaitOk { envelopes }` batch (clone the Values out), (5) DROP the lock. Then process the batch OUTSIDE the lock: for each `serde_json::Value` envelope derive `from`/`to` Principals from its `from`/`to` string fields, call `sign_federation_fields(&mut value, &from, &to, &sk, &vk)`, serialize with `serde_json::to_vec(&value)`, and send via `transport.send(TransportMessage { sender: from, recipient: to, bytes })` (recipient endpoint resolved by the transport's add_peer map, populated in 09-04 keyed by `to`). The short (~1s) Await bounds ingress-Send interleave latency on the shared connection; signing + POST happening outside the lock keeps the connection free for ingress delivery. On `AwaitTimeout` release the lock and continue. On a transport error, log at warn with the principal + recipient and continue (availability, not trust — do not panic the task). Keep the loop tolerant of an empty batch. If any diagnostic helper holds a Write across .await, apply the existing `#[allow(clippy::future_not_send)]` + doc-comment convention (09-RESEARCH §8) rather than restructuring.
