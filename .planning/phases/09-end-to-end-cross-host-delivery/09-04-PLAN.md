<objective>
Wire the egress (09-02) and ingress (09-03) halves into the `famp-gateway` binary: extend argument parsing for the cross-host surface, load the gateway identity + peers keyring, populate the outbound peer-endpoint map, and replace the park-only `ctrl_c().await` with a concurrent run of the inbound listener plus one drain task per backed principal.

This is the composition point where D-01 (back remote principals), D-02 (domain→URL map), D-04 (ingress), and D-03 (egress) become a single running process. Per 09-RESEARCH §7 the process must vary two isolation axes so the E2E can run two copies on one host: `--socket`/`$FAMP_BUS_SOCKET` for bus isolation and `$FAMP_HOME` for identity/keyring isolation.

Purpose: Turn the two dormant halves into a live bidirectional gateway process.
Output: A `famp-gateway` bin that listens, drains, signs, verifies, and delivers.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-10 | Spoofing | wrong signing key at startup | high | mitigate | Identity loaded strictly from gateway_identity_path via load_or_generate; egress signs with it, ingress never signs — separation enforced by which task holds the key. |
| T-09-11 | Tampering | peers keyring load | high | mitigate | Keyring::load_from_file from gateway_peers_keyring_path once at startup; sole writer is `famp peer import` (Phase 8); no runtime auto-pin. |
| T-09-12 | Denial of Service | egress task panic wedges relay | medium | mitigate | run_egress logs-and-continues on transport error (09-02); a per-principal task fault does not silently abort the whole select without a loud exit. |
</threat_model>
